# Quest 宇树参考模式与对照测试

Quest 默认模式为 `unitree_style`，PIKA 参考模式 `pika_style` 为并列可选方案，仅保留这两种 Quest 跟随方式。这是针对固定桌面 OpenArm 的适配，使用项目自己的机器人模型、逆解器、Grip 离合和关节参考生成器。

## 使用

控制台运行 `./app.sh`，选择仿真遥操，“Quest 跟随方式”默认选择“宇树参考（默认）”，可切换“PIKA 参考”；控制器运行期间不能切换。

命令行：

```bash
# 默认宇树参考
./run.sh --sim
# PIKA 参考
VR_TELEOP_MODE=pika_style ./run.sh --sim
```

Grip、夹爪按钮、采集快捷键及循环回放沿用原有操作。先检查前后、左右、上下移动，以及手腕三轴旋转。断流、限位和不可达位置仍由现有控制链处理，现有控制链不提供碰撞检测。

固定参考默认按 OpenXR `-Z → 机器人前方 +X`、`-X → 机器人左方 +Y`、`+Y → 机器人上方 +Z`。操作者方向不一致时，停止控制器后设置一次水平参考角，例如：

```bash
OPENARM_UNITREE_REFERENCE_YAW_DEG=90 ./run.sh --sim
```

该角度绕 OpenXR +Y 轴，运行期间固定，位移和旋转共用同一个变换；转头不会改变机械臂目标。需要仿真核对角度正负，不能直接凭手柄外观认定坐标轴。

## 参考范围

2026-10-12 查阅宇树官方：

- [xr_teleoperate 的逆解实现](https://github.com/unitreerobotics/xr_teleoperate/blob/main/teleop/robot_control/robot_arm_ik.py)：末端位置、旋转、关节正则、相邻解连续性和模型位置限位。
- [TeleVuer 的坐标转换](https://github.com/unitreerobotics/televuer/blob/main/src/televuer/tv_wrapper.py)：显式转换 OpenXR 与机器人坐标，支持忽略头部俯仰及侧倾的水平参考。

本模式采用位置 50、姿态 1、连续性 0.1、名义姿态 0.02 的目标权重，以前一解热启动。逆解是宇树 `G1_29_ArmIK` 的 CasADi/IPOPT，模型换成 OpenArm 单臂 7 轴，关节平滑用他们的四帧加权 `[0.4, 0.3, 0.2, 0.1]`。求解在后台进程里跑，1000 Hz 循环只取 0.30 秒内的最新解；解释器找不到或求解失败时，仍用原来的 LM。`OPENARM_UNITREE_IPOPT=0` 可关掉 IPOPT。需要的环境与宇树文档一致：`conda create -n openarm-unitree python=3.10 pinocchio=3.1.0 numpy=1.26.4 casadi -c conda-forge`。

适配差异：不引入宇树 SDK、TeleVuer/Vuer 会话、人体腰部偏移、手部坐标系 90° 旋转、臂长缩放，也不把他们的 RNEA 力矩发到电机。重力前馈仍走现有的实测关节角和 CAN。姿态标定仍遵守 `--orientation-mapping absolute|incremental`。因此测试结果只评价本适配，不能代表宇树原实现。

实时链路只借用他们「画面和姿态分开、丢了就用最新一帧」的做法。宇树的 WebRTC 是把头上的相机画面送到头显（teleimager，ZMQ 或 WebRTC，WebRTC 优先）；手柄姿态仍走 Vuer 的 WebSocket，控制循环默认 30 Hz。这边头显是透视，不把头上的相机画进视野，所以 WebRTC 用来传手柄姿态：不可靠、不重传。WebSocket 留下做信令、采集回执，以及 WebRTC 没接通时的退路。不访问公网 STUN。控制端把 UDP 排空从 90 Hz 提到 500 Hz，避免包在内核里再等一个 11 ms 的轮询。

## 可复现对照

脚本默认比较当前保留的宇树与 PIKA 两种模式。下方旧版 `human_mimic` 数值为历史记录，已不能通过当前入口运行。

```bash
cmake -S . -B build -DPython3_EXECUTABLE="$PWD/.venv/bin/python"
cmake --build build -j2
.venv/bin/python script/compare_quest_profiles.py --output /tmp/openarm-quest-comparison
```

输出目录必须是新目录。程序仅启动 `--sim`，通过本机 UDP 发送相同的 90 Hz 合成 Quest 输入，覆盖三轴位移、三轴旋转、不可达伸展、松握后移手再接入及 400 ms 断流；正常退出或异常时都会停止仿真子进程。使用仓库内场景，`--xml` 可指定其他场景。

每个模式输出输入 CSV、TCP／关节遥测、控制日志和 `report.json`。报告检查参考关节有限且不超 URDF 位置限位，并给出：

- 实测 TCP 到请求目标的位置 RMSE／P95，实测姿态到请求姿态的角度 P95。
- 逆解耗时 P95、肘关节活动范围及最大相邻参考步长。
- 前后正弦轨迹的相关性估计滞后和三轴跟随增益。

位置误差包含逆解、参考限速和仿真执行误差；不可达目标的请求误差会显著增加，不应混入正常小幅动作的平均值。逆解时间为最近一次求解耗时，遥测中同一求解值可能重复。相关性滞后只估计仿真跟随动态，包含本机桥接及调度，不包含真实 Quest 追踪、Wi-Fi 和视觉链路延迟。默认参数与环境中的调参会影响结果，比较时请使用同一个环境。

新增遥测列在旧列末尾追加：`requested_x/y/z`、`ik_ms`、`steady_s`、`orientation_error_rad`。`tgt_x/y/z` 仍表示关节目标 FK 后的 TCP；不支持请求目标的控制模式对应新增误差列为 NaN。该遥测不改变录制片段和回放 CSV 格式。

## 本地验证

结果和限制见下方验证记录。下述记录来自合成轨迹仿真，不代表真实 Quest、真实相机或真机闭环的测试结果。经过用户现场评价，宇树与 PIKA 已被接受为可替换原默认方案，本次将宇树设为默认。

### 2026-10-12 本机合成输入结果

Ubuntu 22.04、现有虚拟环境、仓库内 MuJoCo 场景，两种模式均运行双臂。下表范围覆盖左右臂与各测试轴；不可达伸展单独评价，不计入普通动作结果。请求位移振幅 35 mm，旋转振幅约 10.3°。两种模式的旋转映射有区别，因此对应旋转测试并非完全相同的机器人关节路径。

| 模式 | 三轴位移 TCP RMSE (mm) | 位移段姿态 P95 (°) | 旋转段姿态 P95 (°) | 普通动作 IK P95 (ms) | 前后估计滞后 (ms) |
| --- | --- | --- | --- | --- | --- |
| `human_mimic`（已移除，历史基线） | 6.65–7.65 | 0.02–0.12 | 2.85–2.91 | 1.071–2.177 | 100 |
| `unitree_style` | 5.37–5.43 | 0.19–0.49 | 2.28–2.43 | 0.205–0.363 | 70 |

新模式在这组小幅轨迹上位置误差、旋转段姿态误差与计算耗时更低；纯位移时姿态保持误差反而略增。伸展到不可达位置时，两种模式均保持参考关节在 URDF 限位内，新模式的请求位置误差没有改善。新模式的肘部活动路径与标准模式不同，不能把肘关节移动更少直接解释成更稳定。

本轮所有参考关节检查通过。普通动作相邻参考步长小于 0.005 rad；松握再接入及断流恢复均完成，仿真正常退出。切换默认后的回归继续检查录制、标注、导出和仿真跟随。

验证：全量 C++ 构建、73 项 Python 回归、两项 Node 检查、录制／停录／标注／二次确认重录／导出仿真及有限／无限循环回放通过。新增回归覆盖两臂倾斜握持下的三轴统一映射、水平标定角、正常与不可达目标的逆解限位，以及界面选择传递到启动器。
