# 左臂相对左手柄方向反了：轴、符号与坐标系诊断

> 本文是历史诊断/规划记录。同向示教功能已移除；涉及该功能的段落不再描述当前代码。


> 本文保留原分支的诊断与规划快照，部分现状已被整合版本更新；本次已实现和已验证的范围见 [整合记录](INTEGRATION_20261012.md)。规划条目不代表已经实现。

基线是 `main` 的 `73dc004`。只读代码，没有改控制、配置或界面，没有接 Quest，也没有跑仿真或真机。主人已确认：左臂跟着左手柄走，但运动方向反了；不是左右臂对调，也不是按键映射。

## 结论

默认模式 `human_mimic` 里，左右手用同一套世界系平移矩阵，左手没有单独乘 −1。网页、UDP 和解析也不按左右手改坐标。因此“只有左臂方向反了”不是报文把左手平移取反。

最可能的原因：左臂 URDF 相对右臂是镜像（肩安装绕 X 差 180°，`joint1` 限位对调，`joint7` 轴是 `0 -1 0` 而右臂是 `0 1 0`）。同向示教用关节符号 `{-1, +1, +1, +1, +1, +1, -1, +1}` 承认 j1、j7 的物理正向与右臂相反。VR 遥操不乘这组符号，逆解直接相信 URDF。右臂若已经跟右手柄同向，而左臂电机正向没有按这个镜像装配，左夹爪就会相对左手柄反向，优先出现在肩部前后/左右（j1）和腕部俯仰（j7）。

第二可能：实际跑的是 `cartesian_precision`。那里的平移增量取自握持瞬间的手柄本体系，旋转增量再右乘到工具系，并且俯仰符号默认 −1。左右柄握持滚转相反时，同一矩阵会把左手的左右和上下一起翻掉，前后仍同向；腕部俯仰还会因为左工具 Y 与右工具相反而单独反。`human_mimic` 的平移和旋转都在机体系/世界系，不受这只滚转影响。两分钟测试用模式切换把这两条分开。

肘部外展和 `joint2` 的单侧 10° 限位会让手臂姿势看起来反，或在顶死后拐向另一边。它们不改变 VR 平移矩阵的符号。`joint2` 顶死已经写在 PR #6 里，当作行程变短；本文件只补充它何时会被看成方向反了。

## 左手数据通路（四种模式共用前半段）

`./run.sh` 默认 `--bimanual`，`VR_TELEOP_MODE` 默认 `human_mimic`，朝向默认 `absolute`（`run.sh` 第 121–128 行）。

1. Quest 页面按 `inputSource.handedness` 取 `gripSpace` 相对 `local-floor` 的位姿，原样写出 `position` 和 `quaternion`。左右手没有额外的轴变换（`quest/client.html` 第 345–391 行）。
2. `quest/quest_bridge.py` 把左手发到 UDP `47912`，右手发到 `47911`。字段顺序左右相同：`timestamp_ms,grip,trigger,px,py,pz,qx,qy,qz,qw,btn_close,btn_open`（第 7–12、107–123、256–261 行）。非双臂时左手包被丢掉；默认启动是双臂，不走这条。
3. `src/io/quest_pose_receiver.cpp` 第 69–77 行按 Eigen `(w,x,y,z)` 组装四元数。左右共用这一个解析函数，接收线程只是绑不同端口。
4. 双臂启动时左右都调用 `setup_arm(..., mirror_y=false)`（`control/openarm_quest_cartesian_control.cpp` 第 5139–5144 行）。单臂同样传入 `false`（第 5341–5342 行）。
5. 之后才按模式分叉。`pika_style` 先调用 `make_human_mimic_config`，平移矩阵与 `human_mimic` 相同。

OpenXR 参考系是 +X 向右、+Y 向上、+Z 向后。共用矩阵（`src/controller/human_mimic_controller.cpp` 第 293–299 行，`src/controller/cartesian_controller.cpp` 第 509–514 行）：

| 手柄世界增量 | 机器人机体系 |
| --- | --- |
| 向前（Δz < 0） | +X |
| 向操作者右侧（Δx > 0） | −Y |
| 向上（Δy > 0） | +Z |

`mirror_translation_y` 为真时只把第 2 行乘 −1，也就是只翻左右。默认 `false`，左右臂都没有打开。矩阵行列式为 +1，是旋转，不会把三根平移轴同时反号。帮助文本写明左右用同一张图、不做 Y 镜像（`control/openarm_quest_cartesian_control.cpp` 第 928 行）。

URDF 把左臂放在机体 +Y（`xyz="0 0.0885 0.698"`），右臂放在 −Y。操作者面向机器人前方（+X）时，上面的表与“手往哪、夹爪往哪”一致，而且左右应相同。

## 四种模式里，方向在哪里被解释

### human_mimic（默认）和 pika_style

平移增量默认是世界系：`delta = p_now - p_grip`，再乘 M（`src/controller/human_mimic_controller.cpp` 第 2507–2513 行）。`OPENARM_HM_POS_WORLD=0` 才改成握持瞬间的手柄本体系。该开关没有左右之分（配置第 691–692 行）。

旋转增量是世界系 `q_now * q_grip^{-1}`，再左乘到机器人锚点上，所以旋转轴在机体系，不在工具系（同文件第 404–423 行）。注释写明不再对滚转/俯仰/偏航单独乘符号；`vr_tcp_pitch_sign` 默认 −1，但只在扳机“只滚转”且该符号为负时共轭一次（第 575–576 行）。默认 +1，左右相同。

因此在默认 human_mimic 下，左手和右手在房间里做同样的平移或转动，送进逆解的机体系目标相同。左夹爪若仍反向，逆解之后的左臂模型或电机正向与右臂不一致。

### cartesian_precision

平移增量先变到握持瞬间的手柄本体系，再乘同一张 M（`src/controller/cartesian_controller.cpp` 第 851–855 行）。左右矩阵相同，但左手握持时的滚转通常和右手相反。绕指向轴转约 180° 时，前后（握持 −Z）不变，左右和上下一起反。

旋转增量是手柄本体系增量，共轭进 M 之后，在工具系里乘 `roll +1`、`pitch −1`、`yaw +1`（第 521–535 行），再右乘到离合器时刻的工具姿态（第 904–905 行）。左臂 `joint7` 轴是 `0 -1 0`，右臂是 `0 1 0`，工具 Y 相反。同一个俯仰符号作用在相反的工具 Y 上，左腕俯仰会和右腕相反。human_mimic 把旋转放在机体系，不受这只工具 Y 影响。

### skeleton_proximal

近端（肩肘）跟身体骨架，远端朝向仍用上面的 human_mimic 重力锁定旋转。骨架方向左右用同一张 `vr_axes`（`src/controller/skeleton_proximal_types.hpp` 第 17–19 行）。`quest/body_tracking.py` 第 24–26 行对左右手臂都做绕 X 的 180°（Quest +Y 上/−Z 前，改成旧骨架系 +Y 下/+Z 前），不单独翻左手。方位角增益左右都是 0.85，没有按臂取反（`skeleton_proximal_controller.cpp` 第 307–321 行）。

肩点缺失时，页面用头显朝向估一个肩，左横向 −0.18 m、右 +0.18 m（`quest/body_tracking.js` 第 57–60 行）。这只影响丢肩关节时的锚点，不反转已经跟踪到的肘腕方向。

### 双臂与耦合

默认双臂：左 UDP 47912 驱动左臂，右 UDP 47911 驱动右臂。耦合打开后左臂改跟右臂末端的相对位姿，不再读左手（`human_mimic_controller.cpp` 第 2402–2403 行）。那是“左手松开控制”，不是“左手方向反了”。下面的测试若握左 Grip 时左臂动、右臂不动，就排除耦合和对调。

## 每种现象对应哪一层

下面按可能性排列。前三条能产生“夹爪平移方向反了”。后两条更像姿势反了或走到一半才反。

### 1. 左臂 j1/j7（以及肩安装）与 URDF 不一致 — 最可能

代码已经核对：默认 human_mimic 的 M、世界系增量和 UDP 字段对左右手相同。右臂方向对、左臂方向反，就落在左链执行上。

同向示教的注释写的是：身体坐标系里要同向，j1 和 j7 的物理轴相反，所以关节角要乘 −1（`mirror_reference.hpp` 第 10–15 行）。README 也把 j1 称为肩部前后摆、j7 称为腕部上下俯仰。VR 逆解输出的是 URDF 角度。真机左电机若按“和右臂相同的关节序号正向”装配，而没有按 URDF 镜像装配，就会出现：

- 主要反前后，并带一部分左右：j1 正向反了。
- 平移大体对，只有腕俯仰反，俯仰还会通过 186 mm 工具臂把夹爪带偏：j7 正向反了。
- 前后仍对，左右和上下一起反：左肩固定关节装成了和右肩一样的 `+90°`，而 URDF 是 `−90°`。

这是假设，需要真机或仿真对照。仿真若用与 `assets/v1.urdf` 一致的 MuJoCo，而只有真机反，就可以把原因收到电机正向或机械安装，而不是 M。

### 2. 笛卡尔模式的握持系增量 — 仅当模式不是 human_mimic 时最可能

同一张 M，作用在左手握持姿态上。绕指向轴约 180° 的握持滚转：前后同向，左右与上下同时反。工具系俯仰符号 −1 再叠加左 `joint7` 轴反向：腕俯仰单独反。

human_mimic 在世界系做平移、在机体系做旋转，握持滚转消在锚点里，不应出现这条。所以“两种模式一样反”就排除握持系；“只有笛卡尔反”就坐实握持系。

代码没有在真机上量过 Quest 左手 `gripSpace` 相对右手的滚转，滚转角度仍是假设。代码已核对的是：笛卡尔确实用握持系增量，human_mimic 默认不用。

### 3. 有人期望左手左右镜像，但代码故意没做

`mirror_translation_y` 存在，双臂启动写死 `false`。打开后只翻该臂的左右（机器人 Y），前后和上下不动。若测试是“只有左右反，前后和上下都对”，并且右臂左右是对的，给左臂打开这个开关能对上症状。它补偿的是左链多出来的一次左右镜像，或操作者希望左臂以外侧为“手的右侧”。它解释不了上下反或三轴一起反。

### 4. 肘往反侧弯，夹爪仍大致跟着走

`outward_dir` 左 +Y、右 −Y，是为了 +φ 指向外侧（`src/controller/virtual_arm_skeleton.cpp` 第 44–48 行）。配置注释写过：曾经翻过这组方向，内扣减轻了，但肘残差和肩 yaw 打架，又改了回来（`openarm_quest_cartesian_control.cpp` 第 248–249 行）。肘 hint 默认关；打开后左符号是 −1。

夹爪平移仍由权重 12 的位置任务拉向 M 的目标。肘反了会让整条臂看起来像镜像，尤其是向外侧伸的时候。若夹爪三个平移方向都对，只是肘在胸口一侧，原因是这条，不是平移符号。

### 5. joint2 顶死后拐向另一边

左紧侧是上限 +0.175 rad（约 +10°），右紧侧是下限 −0.175 rad。仿真默认把紧侧放到 ±60°，真机保持 URDF（第 574–593 行）。限位内逆解仍朝目标走；贴住紧侧后，位置任务可能改用肘和肩 yaw，末端会偏离手柄方向，甚至短时间相反。表现是：小幅同向，大幅或向后/向某一侧时才反或停住。这和 PR #6 的“走得比手短”是同一个限位，不是另一套符号。

## 两分钟判别

仿真或真机都可以。先用默认 `./run.sh --sim`（或已经在用的真机双臂），确认日志是 `HUMAN_MIMIC`。右手做对照：右手柄向前时右夹爪向前。然后只动左手。

1. 握左 Grip，左臂动、右臂不动。握右 Grip，右臂动。这一步确认仍是左手驱动左臂。
2. 从握持点各移约 15 cm，中间回到起点：左手柄向前、向上、向自己的右。看左夹爪，不要看肘。
3. 手柄停住，只做腕部点头（俯仰）和绕指向轴转动。
4. 若手头能改环境变量，再跑一次 `VR_TELEOP_MODE=cartesian_precision ./run.sh --sim`，重复第 2 步。

对照：

| 左夹爪 | 含义 |
| --- | --- |
| 前对、上对、右反；俯仰对 | 只翻了左右。见任务 S1 |
| 前反，上和右大体对 | j1 一类的前后轴反了。见任务 M1 |
| 前对，上反并且右反 | 绕指向轴 180°：笛卡尔握持系，或左肩安装绕 X 差了 180°。用第 4 步分开，见 S2 / M1 |
| 平移对，只有俯仰反 | j7 或笛卡尔工具系俯仰。第 4 步：仅笛卡尔反则 S2，human_mimic 也反则 M1 |
| 夹爪三个方向都对，肘往胸口弯 | 外展方向。见 S3 |
| 小幅对，再往外或往后就停住或拐走 | `joint2` 紧侧。见 L1，并与 PR #6 一起看 |

第 4 步两种模式一样，就不是 Quest 报文，也不是握持系。第 4 步只有笛卡尔反，就不要改 human_mimic 的 M，也不要改电机方向。
