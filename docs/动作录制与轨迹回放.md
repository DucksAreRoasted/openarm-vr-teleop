# 动作录制与轨迹回放

## Quest 遥操录制与回放

1. 运行 `./app.sh`，选择“仿真遥操”或“真机遥操”，按平常流程连接 Quest 并启动控制器。
2. 在“数据采集”填写批次名称，点击“开始录制”，用 Quest 操作双臂及夹爪。
3. 动作完成后点击“数据采集”中的“停止”，再标记成功或失败，保存本段动作。
4. 点击主控制区“停止并释放”，等待遥操控制器退出。
5. 点击“动作回放…”载入最近保存的片段，或在“数据管理”选中片段后点击“回放此条”。
6. 先使用默认的“仿真预览（按录制时间）”和 1 倍原速检查轨迹（也可选 0.5 倍慢速）。源数据单位按录制模式选择：真机录制用“真机夹爪角度”，仿真录制用“仿真夹爪位移”。
7. 点击“到达起手位置”，双臂完整执行你的 Quest 起手轨迹，再平滑衔接到录制首帧并保持，时间停在 0 秒。到位后“开始回放”才可用，点击后播放动作。仿真验证后，可选择“真机回放”，确认 CAN、急停和工作区条件，再按同样的两步操作。回放时无需 Quest 在线。

仿真预览支持拖动进度条定位，松开滑块后跳转到指定时间；播放时跳转后继续播放，暂停时跳转后保持暂停，播完后向前拖动会进入暂停预览，可点击“继续”重播剩余部分。真机回放不提供跳转。

回放支持暂停、继续及停止释放；播放结束会保持末帧，此时可点击“返回录制首帧”。双臂保持使能，从末帧直接平滑返回本次录制首帧，不再重复起手轨迹，到位后等待再次点击“开始回放”，按原速度和次数重新播放同一动作。接入、返回和回放期间均可暂停或停止；到位等待时只可开始或停止，不能拖动进度。更换动作或修改设置需先点击“停止并释放”。录制片段保存在 `recordings/sessions/<批次>/<序号>/`，回放窗口默认读取合并的双臂关节轨迹。

### Quest 手柄采集快捷键

通过 `./app.sh` 启动 Quest 仿真或真机遥操，先在控制台填写批次名称，再刷新 Quest 页面。A/B、X/Y 仍用于夹爪，Grip 仍用于遥操使能。

| 操作 | 功能 |
| --- | --- |
| 左摇杆按下后在 0.4 秒内松开 | 开始录制；录制中则停止录制 |
| 停录后右摇杆短按松开 | 标记成功 |
| 停录后右摇杆按住 1.5 秒 | 标记失败（到点即执行，不必松开） |
| 停录后左摇杆按住 1.5 秒 | 把刚录的片段移到 `recordings/trash/`，下次开始复用该序号。10 秒内再按住一次，或点控制台「撤销丢弃」，可移回原处 |

按住期间约每 0.3 秒轻振一次，满 1.5 秒强振并执行。按住超过 0.4 秒后、未满 1.5 秒就松开，则取消，不触发短按。录制中不能丢弃。必须先停录再标注或重录；待标注时不能开始下一条。标注后仍可重录最近一条。控制台「丢弃重录」立即软删除，10 秒内按钮变为「撤销丢弃」。遥操启动完成前不能录制。断连、追踪丢失或数据间隔超过 250 ms 会取消未完成的按压；恢复后需先松开再按。

控制台接受命令后，成功是一下短轻振，拒绝是两下短振。页面和 PC 日志显示反馈文字，沉浸模式仍不显示网页面板。震动确认的是控制台命令已发送，最终文件是否移入回收站请查看 PC 日志。仅使用 `./run.sh` 时不支持这些快捷键。

快捷键使用独立 UDP 端口 47934，与录制及 TCP 微调端口分开。可用 `OPENARM_QUEST_CAPTURE_PORT` 同时覆盖控制台和桥接进程的端口。地址跟随 `OPENARM_QUEST_UDP_HOST`，默认 `127.0.0.1`；桥和控制台不在同一台电脑且未改这个地址时，快捷键没有反馈。

### 循环播放

在“动作回放”设置“播放次数”：默认 1 遍，设为 2 或以上播放指定次数，设为 0 持续循环，直到停止。仿真预览每遍结束后直接回到首帧，按录制时长继续下一遍。真机每遍结束后保持使能，以首帧接入限速慢速返回首帧，再播放下一遍；返回过程中也支持暂停和继续。指定次数播完后保持末帧。持续循环时可点击“结束循环”，播完当前这一遍后保持末帧，不再进入下一遍；暂停时请求结束循环仍保持暂停，点击“继续”才完成本遍。“停止并释放”仍用于立即退出并失能双臂。保持末帧或首帧等待开始时，可以修改播放次数或选择持续循环，新设置在下一次点击“开始回放”时生效；运动期间锁定次数。

循环返回采用关节位置过渡，不能保证沿录制路径返回，也没有碰撞检测。仿真预览不执行真机的返回过渡，不能用于验证返回路径；录制时尽量让首尾姿态接近。涉及物体的任务还应录入放回和复位动作。

## 录制与回放

1. 在控制台选择 Quest 仿真或真机遥操，启动后握持 Grip 录制双臂动作。
2. 停录并标注，点击主控制区“停止并释放”。
3. 点击“动作回放…”：优先载入日志中最近保存的片段；也可从“数据管理 → 回放此条”载入选中片段。
4. 先选“仿真回放”检查动作，再选择真机、速度和源数据夹爪单位，点击“到达起手位置”。
5. 仿真和真机均先平滑接入你的起手轨迹首帧，完整执行轨迹，再平滑衔接到所选录制动作首帧；到位后保持，等待点击“开始回放”。“暂停”保持当前参考，“继续”接着播放。
6. 播完保持末帧，可先“返回录制首帧”，到位后再次“开始回放”；点击“停止并释放”退出控制器并失能双臂。

默认仿真、1 倍原速，另有 0.25 和 0.5 倍慢速。真机使用控制台的左右 CAN 设置，默认左 `can1`、右 `can0`，接口须已通过控制台配置。回放窗口独占操作，不能与遥操、零重力或标定同时启动。

## 轨迹与夹爪单位

支持片段目录（如 `recordings/sessions/批次/01`）及双臂合并 CSV。可选择文件/目录，也可拖入路径输入框。目录优先读取 `real_teleop_dual_merged.csv`；只有分臂 CSV 时临时合并，不修改录制文件。

CSV 按左 8、右 8 排列，列为 `time,q0,dq0,tau0,...,q15,dq15,tau15`，也接受不含 `tau` 的版本。Quest 遥操片段重放录制的双臂关节动作。历史双臂 CSV 仍按文件里的关节指令播放，不做额外映射。

“真机夹爪角度”对应 −0.98～0.62 rad；“仿真夹爪位移”对应 0～0.044 m。跨仿真/真机回放会显式转换夹爪行程，必须按录制来源选择单位。

## 控制行为

播放前检查整段 CSV 的列、有限数值、递增时间和双臂位置限位，错误文件不进入硬件初始化。记录的力矩与速度不直接下发：位置插值生成速度；真机重力补偿按当前 `gravity_comp.yaml` 重算，仿真预览不加载补偿配置。

录制小数位舍入可能使关节位置略超 URDF 边界。七个臂关节仅容许不超过 `1e-6 rad` 的舍入偏差，并将内存中的位置收回精确边界；超过该范围仍拒绝回放，不修改源文件。日志会显示 `NORMALIZED` 数量。

仿真预览启动时先从默认初始姿态（双肘约 90°）平滑过渡到录制首帧，过渡支持暂停和停止，期间禁止拖动定位。起手过渡不计入回放时间；随后以单调时钟映射 CSV 时间戳，1 倍下录制 1 秒对应现实 1 秒，0.5 倍对应现实 2 秒。暂停冻结播放时间，继续时排除暂停耗时。关节和夹爪直接恢复插值姿态，不经过真机限速或追赶暂停；渲染约 60 Hz，渲染卡顿时跳过过期显示样本，下一帧追上时间轴。循环直接回首帧，播完保持末帧。这是数据预览，不是动力学或真机控制验证。

真机控制频率为 200 Hz。没有起手文件的直接接入以及自动循环返回限速为 0.3 rad/s、0.6 rad/s²；衔接录制首帧、正常播放时七关节为 0.6 rad/s、1.2 rad/s²；起手轨迹本体使用与 Quest 相同的公共 follower 控制，夹爪为 1 rad/s、4 rad/s²。目标跟不上时冻结轨迹时间等待追赶，因此所选倍率是上限，实际播放时间可能更长。保留实测速度阻尼、J1–J6 为 2 rad/s、J7 为 3 rad/s 的实测超速停机保护、力矩上限、CAN 新鲜度与电机故障检查；夹爪沿用反馈限差和疑似接触柔和保持。

软件限位不包含碰撞检测。当前仿真后端直接跟随位置，能验证流程和数据，不能验证真机力矩稳定性。

实机回放现直接复用遥操 follower 控制器，增益、重力模型/倍率/渐入、夹爪接触保持和安全过滤共用。旧回放腕部 3 Nm 的 PD＋FF 总力矩抵消策略已被替换；当前与遥操一致，腕部 2 Nm 仅限制重力前馈，位置 PD 正常叠加。CAN 新鲜度、J1–J6 为 2 rad/s、J7 为 3 rad/s 的实测速度停机、0.45 rad 跟踪误差保护仍保留。详见 [J7 调查、对齐与采集](J7_REPLAY_ALIGNMENT.md)。

## 命令行

```bash
# 仿真回放（默认 1 倍原速）
.venv/bin/python script/replay_teaching.py recordings/sessions/批次/01 --sim
# 仿真持续循环（真机录制来源）；仿真录制来源另加 --source-meters
.venv/bin/python script/replay_teaching.py recordings/sessions/批次/01 --sim --repeat 0
# 离线检查，不使能电机
.venv/bin/python script/replay_teaching.py recordings/sessions/批次/01 --real --check
# 真机接口须已配置
.venv/bin/python script/replay_teaching.py recordings/sessions/批次/01 --real --speed 0.25
```

环境变量 `OPENARM_MUJOCO_XML` 指定仿真场景，`OPENARM_GRAVITY_YAML` 指定补偿文件。未设置场景时，回放和 `run.sh` 用同一条规则：若本机仍有 `/home/ducks/motion-trajectory-studio/model_library/OpenArm_V1/scene_table.xml` 就用它，否则用仓库内 `models/OpenArm_V1/scene_table.xml`。控制台启动时使用 `--wait-for-start`，到位后等待标准输入 `play` 才播放；播完可发送 `prepare` 返回首帧并再次等待 `play`。命令行省略该选项时保留自动播放，也支持旧 `restart` 指令。标准输入另接受 `pause`、`resume`、`finish_loop`（完成当前遍后保持）、`stop`；仿真预览接受 `seek <秒数>`（当前遍内的时间，超出范围时限制到首尾帧，到位等待和接入时禁止跳转）；Ctrl+C 也会退出并释放双臂。

## 排查回放问题

窗口每次回放都会将启动参数、控制器输出、报错和退出状态保存到 `/tmp/openarm_teaching_replay_日期_时间_进程号.log`，路径显示在窗口日志首行，并写入控制台日志。可用 `ls -t /tmp/openarm_teaching_replay_*.log` 找到最近一次；关闭窗口后日志仍保留。

起手轨迹默认使用 `assets/steady_action_on_table.csv`（约 6.43 秒），与 Quest 遥操启动共用 `OPENARM_QUEST_STARTUP_FILE` 配置。命令行可通过 `--startup-file 路径.csv` 覆盖。起手文件的夹爪单位为电机弧度，与所选录制动作的单位设置独立；启动控制前会检查两个文件。首次准备完整执行这条轨迹；播完后的手动返回直接平滑连接末帧与录制首帧，不重复起手轨迹，到位后仍需手动开始。自动循环间的返回方式不变。真机保留公共 follower 的安全过滤、反馈与力矩检查。起手段按与 Quest 共用的时间轴执行（含高速片段局部重定时）；只有后续衔接录制首帧时会等待追赶。

起手轨迹默认按原始时间轴执行，不随动作回放的慢速选项缩放；高速片段会局部重定时，为实测超速停机留出余量。遥操与回放共用 `StartupTrajectory`：使用同一份 CSV 的位置与速度、同一个 S 曲线接入生成器和末端保持时间。默认接入 5 秒（`OPENARM_QUEST_STARTUP_TRANSITION_SEC`，已到位可跳过），轨迹本体约 6.43 秒，末端保持默认 0.6 秒（`OPENARM_QUEST_STARTUP_HOLD_SEC`）。起手段不再叠加回放参考整形或追赶暂停，仍经过公共 follower 的安全过滤。回放额外的录制首帧衔接使用原有限速和追赶保护，界面分别显示“执行起手轨迹”和“衔接录制首帧”及各自耗时。

起手速度余量修复：2026-10-12 的实机日志出现右侧 J7 实测 −3.02564 rad/s，超过保留的 3 rad/s 停止阈值。共享起手执行器对接近阈值的片段做局部时间拉伸，指令速度目标使用实测停止阈值的 65%，并结合 20 ms 位置窗口识别录制速度低估；时间拉伸系数平滑衔接，完整保留录制位置和顺序。当前起手文件本体由 6.433 秒调整为约 6.957 秒，接入和末端保持另计。修改仅在内存中进行，源 CSV 不变，左右臂超速、位置、跟踪误差及 CAN 停止检查继续生效。简化动力学回归复现原始 J7 速度超调并验证修正后的速度余量；该模型不替代真机验收。

第二次手动回放的返回准备在后台构建：CSV 读取、速度重定时及 S 曲线生成不再占用实机 200 Hz 控制线程。窗口先显示“准备返回轨迹，保持末帧”，期间持续读反馈并发送保持指令，随后直接平滑返回录制首帧，到位后再次等待手动开始。停止仍可立即失能双臂；后台规划失败走正常报错停机路径，50 ms 控制截止时间保护继续生效。此变更修复了 `20261012_174907` 日志中 `command=prepare` 后因同步重建轨迹触发的 `replay servo deadline missed`。

## 离线平滑录制动作

停止遥操后，打开“数据管理”，选择已录制片段，点击“平滑此条…”。选择轻度（80 ms）、标准（120 ms）或较强（200 ms），默认单关节最大位置改动为 3°。点击“生成平滑副本”，完成后可查看最大改动与速度 RMS，再点击“回放平滑副本…”进入原有回放窗口，先用仿真检查动作。

输出保存在所选片段的 `processed/smooth_<时间>_<随机标识>/`，每次生成独立目录：

- `real_teleop_dual_merged.csv`：平滑后的双臂轨迹，可直接选择该目录回放。
- `smoothing_report.json`：源数据路径及哈希、参数、位置改动和速度统计。
- `lerobot_actions_smoothed.csv`：存在训练 CSV 时额外生成的动作指令副本。
- 原片段的录制来源元数据和标签（存在时）随副本保存。

只平滑两臂各七个关节的位置，并重新计算对应速度；夹爪位置与速度、原始时间戳和轨迹时长保持原样。算法先按时间均匀采样、进行对称高斯滤波，再映射回原始采样时刻，不增加整体时延；首尾区域逐渐减弱滤波以保留精确首尾位置。每关节使用整段统一系数约束最大改动，避免逐帧硬截断带来的折点。输出位置不超出源数据每关节的最小值和最大值；这不是碰撞或关节速度保证，回放仍执行原有检查与保护。

训练指令副本只修改 `l_act0..6/r_act0..6`，保留实测 obs、夹爪动作和时间戳。它按训练指令流自己的采样时刻处理，不会改写图像、实际观测或已导出的数据集。当前“导出”按钮继续导出原始录制；平滑动作文件需在确认接触过程、动作与观测对应关系后显式用于训练，不能把滤波结果当成新的真实测量。源轨迹中的 tau 列保留为历史日志，未重算，现有回放器也不使用这些记录力矩。

命令行也可生成副本，无需连接机器人：

```bash
.venv/bin/python script/smooth_recording.py recordings/sessions/<批次>/<序号> \
    --window-ms 120 --max-deviation-deg 3
```

可用 `--output-root /tmp/smoothed-review` 将副本放到其它目录。支持合并 CSV，以及由现有回放读取器合并的左右分臂录制。输入必须有限、时间严格递增；检测到较长采样间断会拒绝跨间断平滑。较强平滑会钝化快速转向和接触动作，应结合预览选择强度。该功能减少已有动作中的高频抖动，不会消除实时遥操链路本身的抖动，也不保证所有任务的训练效果都改善。
