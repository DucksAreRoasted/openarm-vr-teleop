# Quest 肘部与腕部遥操

控制台选择“仿真遥操”，勾选“Quest 肘部与腕部追踪”，启动后刷新 Quest 网页并进入沉浸模式。命令行也可使用：

```bash
./run.sh --skeleton --sim
```

此模式持续从 WebXR 身体追踪接口读取左右肘部 `arm-lower` 与腕部 `hand-wrist`，不再逐帧要求肩部数据。每次进入沉浸模式，首次有效帧读取肩部 `arm-upper` 作为固定参考；若不可用，则以当时头显位置和朝向估算肩点（左右偏移 18 cm、向下 20 cm、向后 5 cm）。肩点估计不等于真实肩部测量；操作时尽量保持躯干位置，移动躯干后退出并重新进入沉浸模式校准。肘部和腕部仍必须有有效身体追踪数据。计算肩参考→肘、肘→腕方向及骨长。控制器使用上臂抬升/方位与肘部弯曲的变化控制前四个关节，手柄朝向控制后三个关节，A/B/X/Y 控制夹爪。Grip 握持时跟随，松开保持；每次重新握持会以当前人臂和机器臂姿态建立相对映射。Trigger 沿用该控制器原有的回到准备姿态操作。

这里跟随的是上臂方向和肘部弯曲，不保证人臂和机器人骨架逐点重合；人机骨长不同，前臂弯曲平面从握持时的机器人姿态建立并随上臂方向传递。手柄末端位置不再作为独立的定位任务。若任务需要严格的末端位置，取消骨骼模式后重启遥操。

## 浏览器支持与状态

使用设备自带的 Quest 浏览器。骨骼模式下网页会请求必需的 `body-tracking` 权限；不支持或拒绝时会话启动失败，不会静默进入无骨骼的遥操会话。具体可用性取决于设备、浏览器版本、设置和授权。为保持视野干净，沉浸模式没有悬浮面板；退出后在网页“肘腕追踪”一栏查看最近一帧的左右臂状态。运行日志应包含 `teleop_mode=SKELETON_PROXIMAL`，`HUMAN_MIMIC` 仅表示虚拟骨骼模式。若提示未获得身体追踪，检查权限及浏览器 `chrome://flags` 中是否提供 WebXR Experiments / 身体追踪选项，修改后重启浏览器；该选项并非所有版本都有。

不支持、拒绝授权、关节位置不可用或被标记为模拟位置时，不会从手柄位置猜测肘部，也不会自动切回末端控制。可以取消控制台的骨骼模式，重启后继续使用原遥操。

接口及关节名称依据 [WebXR Body Tracking 草案](https://immersive-web.github.io/body-tracking/)。身体关节由设备运行时提供，不能据此保证测量精度；手指追踪接口与肩肘身体追踪不同。

控制台日志 `[quest-bridge][skeleton] left=… right=…` 会报告桥接验证后的状态：`valid` 有效；`missing_body_payload` 未发送骨骼消息（检查网页版本和模式）；`no_body` 浏览器未提供身体接口；`missing_joint` 关节接口缺失；`unavailable_pose` 姿态不可用；`emulated_position` 位置被浏览器标记为模拟位置；`invalid_geometry` 坐标或骨长校验失败；`timestamp_mismatch` 骨骼与手柄消息错帧。诊断仅写入日志和普通网页，不创建沉浸悬浮面板。更新后需重启遥操桥接并重新打开 client v24 网页。

## 数据与保持行为

同一 WebSocket 消息携带手柄和骨骼数据。桥接将 Quest 的 +Y 向上坐标通过绕 X 旋转 180° 转为已有骨骼控制器的 +Y 向下坐标，向本机 UDP `47951` 发送骨骼方向；`OPENARM_SKELETON_POSE_PORT` 可同时修改桥接和控制器端口。缺失或不合理的骨长、非有限坐标、错帧时间戳会使对应臂的数据无效。

短暂骨骼丢失时，该臂立即冻结所有手臂关节参考，最多保留 Grip 接入状态 120 ms。此间恢复且 Grip 仍握持，会以当前关节位置和最新追踪姿态重新建立相对映射，不追赶丢失期间动作。持续丢失、骨骼年龄超过 250 ms 或手柄断流超过 250 ms 时退出跟随，恢复后需重新握持 Grip；另一臂可以独立继续。手柄数据超过 50 ms 未刷新时先冻结，包括扳机复位和夹爪按钮，不执行旧帧动作；在硬超时之前恢复时重新建立映射接入。首次控制命令从实际测量关节位置（包括夹爪）建立；松开 Grip 时立即冻结已有参考，不继续追赶旧目标。保持位置仍需要电机出力，不等于电机失能。原有限位和关节速度/加速度限制继续生效。网页采样/发送及骨骼逆解均限制为最高约 60 Hz，关节参考维持原控制循环频率；沉浸模式不再更新不可见的手柄数据面板。真实机械臂的启动轨迹仍按原启动配置执行。

先在仿真中核对左右、抬臂、转动和弯肘方向，再进行实物验证。录制保存实际发出的机器人关节命令，可沿用现有回放流程，不要求回放时身体追踪在线。

## 验证

- `cmake --build build --target quest_cartesian_control skeleton_control_smoke -j2`
- `.venv/bin/python -m unittest discover -s tests -p test_body_tracking.py`
- `node tests/test_body_tracking.cjs`
- `node tests/test_quest_session.cjs`
- `build/skeleton_control_smoke assets/v1.urdf "$OPENARM_MUJOCO_XML"`：需要有效的 V1 双臂场景路径。无窗口运行项目现有的 MuJoCo 位置命令仿真后端（直接设置关节位置并执行前向计算，不验证动力学或真实电机响应）。检查双臂初始位置保持、静止握持不偏移、骨骼/手腕关节变化、URDF 限位、松开保持、丢失/过期保持、短暂丢帧冻结/恢复无跳变、长时间丢失后重新握持，以及旧扳机和夹爪按钮不继续动作。

上述验证不连接 CAN，也不驱动真机。尚未使用 Quest 实测浏览器关节可用性、无线链路与硬件跟随效果。
